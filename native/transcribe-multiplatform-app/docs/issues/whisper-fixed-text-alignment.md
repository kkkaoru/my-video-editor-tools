# Whisper の時刻を、文字を固定した処理で求める

**結論: 採用済み。** whisper.cpp を 2 回実行するのをやめ、flash attention のまま 1 回の実行で文字と時刻を出す。文字起こしの処理時間は今までの 0.44 倍になった。

## 背景

字幕の文字と時刻を両方良くするため、whisper.cpp を 2 回実行していた。

| 実行 | 設定 | 使うもの | 捨てるもの |
|---|---|---|---|
| 1 回目 | 通常(flash attention あり) | 文字 | 時刻 |
| 2 回目 | `-nfa -dtw large.v3.turbo` | 時刻 | 文字 |

2 つの実行は別々に文字を出すので、文字を対応づけて時刻を写し、片方にしかない文字の時刻は前後から推定していた。

## 実現方法

`whisper_full` の DTW は、もとから確定した文字を固定してデコーダに 1 回通している。探索はしていない。2 回目が遅かったのは、エンコーダと探索をもう一度すべて回していたから。

DTW に必要なのは softmax(K·Q) だけで、K は flash attention のときもキャッシュに残っている。そこで `scripts/release/whisper-cpp.patch` で次の 2 点を変えた。

- DTW の強制デコードのときだけ、flash attention の計算とは別に重みを計算する。通常のデコードのグラフは変わらないので、文字は変わらない。
- flash attention のときに DTW を止めていた初期化の処理を消す。

C API だけでは実現できない。必要な関数が static で、`whisper_decode` には重みを保存する引数がない。パッチの残りは、clang-cl で Alder Lake 用の CPU 版がビルドできるようにする 3 行。

## 測定

Apple Silicon の Mac で実測した。時刻は Nemotron 3.5 の単語時刻を基準にしたもので、基準は人が確かめた正解ではない。Nemotron は `漬` などの文字を含む区間では単語時刻を出さないので、横のクリップと全尺は 10 秒ずつ区切り、出せた区間だけで測った。誤差は文字の差分で対応がついた単語の頭の時刻で比べた。以前の 0.22 秒、0.52 秒とは測り方が違う。

### 処理時間(whisper-cli の total)

| | 通常の 1 回 | `-nfa -dtw` | 今までの 2 回(足し算) | 新方式 | 倍率 |
|---|---|---|---|---|---|
| 横 2431 秒 | 141.9 秒 | 182.0 秒 | 323.9 秒 | 142.9 秒 | 0.44 |
| 縦 5136 秒 | 306.9 秒 | 394.0 秒 | 701.0 秒 | 311.1 秒 | 0.44 |
| 横 2 分、CPU(`-ng`) | 105.7 秒 | 147.4 秒 | 253.1 秒 | 100.6 秒 | 0.40 |
| 縦 30 秒、CPU(`-ng`) | 36.0 秒 | 52.5 秒 | 88.5 秒 | 38.7 秒 | 0.44 |

全尺は各 1 回。CPU も各 1 回。Metal の短いクリップは別の処理と重なって値がばらついたので、表に入れていない。

メモリのピークは全尺で 2.5〜3.0 GB(新方式)。

`ffmpeg silencedetect` で、字幕の開始から音声の開始までを測った。今までの方式と新方式は、`engines.rs` だけを変えて同じ作業ツリーからビルドしたアプリで出した。

| 縦 30 秒 | -35 dB | 0(0) | 0(0) |
| 縦 30 秒 | -30 dB | 0(0) | 0(0) |
| 横 2 分 | -35 dB | 1(0) | 1(0) |
| 横 2 分 | -30 dB | 3(0) | 2(2) |
| 横 2431 秒 | -35 dB | 2(2) | 2(2) |
| 横 2431 秒 | -30 dB | 14(4) | 9(4) |
| 縦 5136 秒 | -35 dB | 16(8) | 8(3) |
| 縦 5136 秒 | -30 dB | 52(23) | 22(10) |

横 2 分の 2 件のうち 1 件は、82.63 秒の相づち `ん` で、実際の音は 79.6〜80.5 秒付近にある(無音の検出から見た推定)。1 回目のセグメント分けで、次のセグメントの頭に入ったため。

### 文字

通常の 1 回と新方式で、トークンの id と文字が全部一致した(Metal: 30 秒、2 分、全尺 2 本。CPU: 30 秒、2 分)。`scripts/verify/whisper-dtw-text.sh` で確かめられる。パッチや whisper.cpp を更新したら実行する。

### 字幕の切れ目

縦 30 秒は `っちゃった` と `でもねぇ` を含めて今までと同じ。横 2 分は単語の文字は同じで、切れ目が数か所変わった(たとえば `ちゃばば` / `ばばばまださっき…` が `ちゃばばばばば` / `まださっき…` になった)。

### 探索の設定だけで 2 回目を軽くする案

`-bs 1 -bo 1 -nf` は横 2 分で 2 回目が 4.99 秒から 4.13 秒(約 17% 減。1 回ずつ)。時刻は新方式より悪かった(平均誤差 0.103 秒)ので採用しない。

## セグメントの境界

1 回目のセグメントの境界は DTW より粗く、そのまま押し戻すと単語が境界に積み上がった(縦の全尺の均等 4 区間で、早出し 24 件)。`engines.rs` の `warped_start` は境界の外 1 秒までを信じる。0.5 秒、1 秒、2 秒、無制限を測り、1 秒以上で差がなかった。無制限にしないのは、セグメントから数秒外れる token が実際にあるから。

## 動作の変化

- DTW が落ちると、GPU なら CPU で全部やり直す。CPU でも落ちたら DTW なしで実行する(荒い時刻で続く)。今までは 2 回目だけが失敗して荒い時刻で続いた。
- 進捗は 2 回分の配分がなくなり、1 回分になった。

## 保守の負担

- whisper.cpp を更新したら、`whisper-cpp.patch` を載せ直して `whisper-dtw-text.sh` を実行する。
- Windows の CPU 版は公式のビルドをやめ、自前でビルドする(`fetch-runtime.sh`)。CPU の機能ごとの `ggml-cpu-*.dll` は公式と同じ形。

## 未確認

- Vulkan での動作。手元に GPU のある Windows がない。DTW が Vulkan だけで失敗すると、CPU でやり直すか、最後は荒い時刻になる。処理は止まらないので、時刻が悪くなっても気づきにくい。
- GitHub の CI(MSVC)でのビルド。Mac からのクロスビルドは Radeon 版と GeForce 版の両方が通った。CI の CPU 版はターゲットを絞らず examples をすべてビルドするので、時間が延びる。

Windows 11 ARM の VM(GPU なし)での確認は次のとおり。

- Mac からクロスビルドした Radeon 版のインストーラで、30 秒のクリップを最後まで処理できた。
- 自前の CPU 版の `whisper-cli.exe` を直接実行した。`ggml-cpu-haswell.dll` を読み込み、flash attention と DTW が両方有効で、77 トークン中 70 に `t_dtw` が付いた。

## 対象外

- 文字の誤認識を減らすこと(`増えこえって` など)。この変更は時刻だけを扱う。
- 時刻合わせ専用の別モデルの追加。
