# Whisper の時刻を、文字を固定した処理で求める

## 背景

字幕の文字と時刻を両方良くするため、whisper.cpp を 2 回実行している(`src-tauri/src/engines.rs` の `transcribe`)。

| 実行 | 設定 | 使うもの | 捨てるもの |
|---|---|---|---|
| 1 回目 | 通常(flash attention あり) | 文字 | 時刻 |
| 2 回目 | `-nfa -dtw large.v3.turbo` | 時刻 | 文字 |

- DTW は cross-attention の重みから文字ごとの時刻を求める。flash attention はこの重みを作らないので、2 回目は `-nfa` が必要になる。
- 2 つの実行は別々に文字を出すので、文字を対応づけて時刻を写している。片方にしかない文字の時刻は、前後から推定している。

## やりたいこと

2 回目の探索をなくす。1 回目の文字を固定してデコーダに通し、その cross-attention の重みに DTW をかけて時刻を求める。

## 期待する効果

- **処理時間:** 探索が要らないので、2 回目が速くなるはず。
- **文字:** 1 回目のままで変わらない。
- **時刻:** 正しい文字そのものに対して時刻を求めるので、文字の対応づけと前後からの推定がなくなる。

## 現在の測定値

Apple Silicon の Mac で、Nemotron 3.5 の単語時刻を基準に測った。基準は人が確かめた正解ではない。

| 項目 | 通常の 1 回 | 今の 2 回 |
|---|---|---|
| 時刻の平均誤差(30 秒の縦クリップ) | 0.52 秒 | 0.22 秒 |
| 200 ms を超える早出し(同上) | 8 件 | 0 件 |
| 横 2431 秒の動画の文字起こし | 90 秒 | 195 秒 |
| 縦 5136 秒の動画の文字起こし | 179 秒 | 424 秒 |

処理時間は Nemotron を同時に動かしていた時間を含むので、単独ならもう少し短い可能性がある。

## 調べること

着手を決める前に、小さく測る。

1. **実現方法:** whisper.cpp の C API だけで実現できるか、ソースの改造が必要か。トークンを指定してデコーダを動かし、cross-attention の重みを取り出す手段があるか。
2. **Rust からの呼び方:** 今はコマンドを起動している。ライブラリとして呼ぶか、専用のコマンドを作るか。
3. **エンコーダ:** 別の実行にすると、エンコーダが 2 回動く。処理時間のうちエンコーダが占める割合を測る。1 つの実行で共有できるか。flash attention の設定はコンテキスト単位なので、共有できない可能性がある。
4. **長い動画:** 30 秒の窓と 1 回目の文字の対応づけ。窓の境界をまたぐ文字の扱い。

## 判断の基準

次をすべて満たすなら採用する。数値は測定 3 の後で決める。

- 時刻の精度が今の 2 回実行と同等以上。
- 文字起こしの処理時間が、今の 2 回実行より十分短い。
- 下の保守の負担に見合う。

満たさなければ、今の方式を続けて、この Issue は閉じる。

## 保守の負担

- whisper.cpp を改造する場合、更新のたびに改造を載せ直す。
- macOS の Metal 版、Windows の CPU 版、Vulkan 版のすべてを、改造した版でビルドして検証する。Windows の CPU 版は今は公式のビルドを使っているので、自前のビルドに変わる(`scripts/release/fetch-runtime.sh`)。
- 取得物のハッシュ固定と `THIRD_PARTY_NOTICES.md` を更新する。

## 完了の条件

- `engines.rs` の 2 回目の処理を置き換える、または不採用の理由を記録する。
- 文字が 1 回目と完全に一致することを、テストで固定する。
- 30 秒の縦クリップ、2 分の横クリップ、全尺 2 本で、時刻の精度と処理時間を今の方式と比べる。
- `っちゃった` と `でもねぇ` のような間のある箇所で、字幕の切れ目が崩れないことを確かめる。
- macOS と Windows(GeForce、Radeon)のビルドが通る。

## 対象外

- 文字の誤認識を減らすこと(`増えこえって` など)。この変更は時刻だけを扱う。
- 時刻合わせ専用の別モデルの追加。
